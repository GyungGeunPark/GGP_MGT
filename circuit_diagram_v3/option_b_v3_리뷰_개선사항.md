## 1. 정상 확인된 항목 (그대로 진행 OK)

이미지·핀맵과 대조해 **올바른** 것으로 확인된 설계 결정입니다.

- ✅ **UART 크로스 배선**: 센서 TX → GPIO20(RX), GPIO21(TX) → 센서 RX.
  `ESP32_C3_pinmap.png` 확인 결과 GPIO20=RX, GPIO21=TX가 맞음. 회로도·배치도·가이드 3곳 모두 일치.
- ✅ **ADC 핀 선택(GPIO3 = ADC1_CH3)**: ESP32-C3에서 ADC2는 WiFi 사용 시 막히지만 **ADC1은 WiFi와 공존 가능**. GPIO3은 ADC1이므로 WiFi UDP 모드에서도 배터리 측정이 정상 동작 — 좋은 선택.
- ✅ **3V3 핀 직접 급전**: Pololu 3.3V → ESP32 3V3 핀으로 온보드 LDO 우회. 효율상 타당(단 1.4절 주의 참고).
- ✅ **1:1 전압분배(220k/220k)**: 배터리 3.0→1.8V를 1.5→0.9V로 매핑, ESP32 ADC 선형 구간에 들어옴.
- ✅ **전압분배기는 홀더 스위치 이후(스위칭된 BAT+)에서 분기** → OFF 시 누설 0 주장과 일치.
- ✅ **AO3401 소프트스위치 제거** 결정 자체는 사람이 직접 ON/OFF 하는 용도에 합당.

## 2. 치명적 / 높은 우선순위 문제

### 🔴 C-1. ADC 필터 캐패시터: 100µF 전해 → 측정 불능 수준

**증상**: `option_b_guide_v3.md` §1.3, §3 Step 3, 회로도/배치도 모두 ADC 분배점 필터로 **100µF 16V 전해**를 지정("10µF 대신 사용, 필터링 성능 향상").

**근거 (Claude·Gemini 동일 결론)**:
- 분배점 소스 임피던스 = 220k ∥ 220k = **110kΩ**
- 시정수 τ = 110kΩ × 100µF = **11초**
- 1% 정착까지 5τ ≈ **55초**. 그런데 펌웨어는 부팅 ~1초 뒤 `setup()`에서 첫 배터리값을 읽음 → 그 시점 충전율 = 1−e^(−1/11) ≈ **8.7%** → 첫 측정값이 실제의 약 9%로 완전히 틀림.
- **누설 전류 오차**: 알루미늄 전해는 누설(보통 1~16µA)이 큼. 분배기 총 전류가 3.0V/440k = **6.8µA**뿐이라, 전해 누설 수 µA가 그대로 분배점 전압을 끌어내려 **배터리 잔량을 상시 과소 표시**. 온도 의존성까지 더해짐.

**권장 수정**:
- ADC 필터를 **100nF~1µF 세라믹(무극성, 저누설)**으로 교체. (가이드의 §1.3 "10µF 대신 100µF" 권고는 **반대로 가는 변경**이므로 철회.)
- 추가로 분배 저항을 낮추면 더 안정적: **100kΩ/100kΩ**(소스 50kΩ)면 τ도 줄고 누설 영향↓, 누설전류는 15µA로 여전히 미미.
- 펌웨어: 부팅 첫 배터리 읽기 전에 충분한 딜레이를 두거나, 첫 1~2회 측정값은 버릴 것.

---

### 🔴 C-2. 저전압 경고 임계값 < 컨버터 차단 전압 → 경고가 절대 안 뜸

**증상**:
- `option_b_guide_v3.md` §6: `#define LOW_BATT_THRESHOLD_B 2.2` (2.2V 미만 경고)
- 잔량표(§6): 2.0V=0%, 2.4V=20% 경고로 매핑
- 전원경로 다이어그램(§2.1): "3.0V(신품) ~ 1.8V(방전)" — 1.8V까지 쓸 수 있는 것처럼 표기

**근거 (Gemini 지적 + 데이터시트)**: Pololu S7V8F3의 **최소 입력 ≈ 2.7V**(UVLO). 부하·내부저항으로 단자전압이 2.7V 밑으로 떨어지면 컨버터가 **3.3V 출력을 끊음**. 즉 시스템은 2.7V 부근에서 **그냥 꺼짐**. 그런데 경고 임계값 2.2V는 그보다 **낮아서 도달 전에 이미 사망** → 사용자는 경고를 한 번도 못 봄. §2.1의 "1.8V까지" 표기, §6의 2.0V·2.4V 매핑은 이 컨버터에선 **도달 불가능한 영역**.

**권장 수정**:
1. `LOW_BATT_THRESHOLD_B`를 **2.8~2.9V**로 상향(컨버터 차단 직전에 경고가 뜨도록).
2. §2.1 전원경로의 "1.8V(방전)"을 **"~2.7V(컨버터 차단)"**로 정정.
3. §6 잔량 매핑표를 컨버터 차단점 기준으로 재작성(예: 3.0V=100%, 2.85V=20% 경고, 2.7V=0% 차단).
4. (선택, 더 나은 대안) 알카라인 용량을 끝까지 쓰려면 **더 낮은 입력에서 동작하는 부스트/벅부스트**(예: Pololu U3V70F3, TPS61xx 계열, 최소 입력 ~0.8~1.0V)로 교체 검토. 현재 구성은 알카라인 잔여 용량의 상당 부분을 못 씀 → §9 런타임(~8h)도 **낙관적**.

---

### 🟠 C-3. GPIO2 = 스트래핑 핀을 센서 EN 구동에 사용

**증상**: §2.4, §3.3, 배치도 모두 `GPIO2 → 센서 EN(선택)`.

**근거**: ESP32-C3의 스트래핑 핀은 **GPIO2, GPIO8, GPIO9**. GPIO2는 리셋 순간 레벨이 샘플링되며 **부팅 시 HIGH/플로팅이 안전**. 센서 EN 입력이 부팅 시 GPIO2를 LOW로 끌거나 플로팅 상태로 두면 **간헐적 부팅 실패/모드 진입** 위험.

**권장 수정**:
- EN 제어가 필요하면 **비(非)스트래핑 핀으로 변경**: 예) GPIO10, GPIO7, GPIO6, GPIO5(기능상 여유). GPIO10이 가장 깔끔.
- GPIO2를 꼭 유지해야 하면 **GPIO2–3.3V 풀업 저항(예: 10k)** 추가해 부팅 시 HIGH 보장.
- EN을 안 쓸 거면(센서는 EN 미연결 시에도 동작) **EN 선을 아예 빼는 것**도 단순화에 도움.

> 참고: GPIO8(온보드 LED)도 스트래핑 핀이지만 보드가 부팅 시 HIGH를 만족하도록 설계돼 있어 상태표시 용도는 OK. 다만 외부에서 GPIO8을 LOW로 당기지 말 것.

## 3. 중간 우선순위 문제

### 🟡 M-1. WiFi 버스트 + 알카라인 내부저항 → 브라운아웃/재부팅

**근거 (Claude·Gemini 동일)**: 방전된 알카라인은 내부저항(ESR)이 커짐. WiFi TX 피크(>300mA)가 들어오면 컨버터 입력 전류가 (2.7V 부근에서) 400~500mA로 치솟아 **단자전압이 UVLO 밑으로 순간 강하 → 리셋 루프**. 가이드 §8 트러블슈팅에 "470µF 추가" 언급은 있으나 사후 대처임.

**권장 수정**:
- **사전 예방**으로 3.3V 버스에 **470µF 이상 벌크 캡** + 컨버터 VIN 측에도 **100~220µF** 배치(설계에 처음부터 반영).
- 배터리 동작 시 **BLE 모드 우선** 권장을 더 강하게 명시(현재 표현 유지하되 "WiFi는 신품 전지 + 벌크캡 필수" 경고 추가).

### 🟡 M-2. ESP32-C3 ADC 비선형 — 캘리브레이션 필요

**근거 (Gemini 지적)**: ESP32-C3 ADC는 `ADC_11db`에서 양 끝이 비선형이고 칩별 오프셋이 큼. 단순 `adcV = raw*(3.3/4095)`는 오차가 큼.

**권장 수정**: ESP-IDF/Arduino의 **eFuse 캘리브레이션 API**(`analogReadMilliVolts()` 사용 또는 `esp_adc_cal`)로 보정. §8 트러블슈팅의 "보정계수 적용"을 코드 레벨로 구체화.

### 🟡 M-3. Pololu SHDN 핀이 설계/BOM/배치도에 명시 안 됨

**근거 (`Pololu.png` 대조)**: 실제 S7V8F3 보드에는 **SHDN(셧다운) 핀이 존재**(핀: SHDN, VIN, GND, VOUT, GND). 가이드·회로도·배치도는 모두 **VIN/GND/VOUT/GND 4핀**으로만 다루고 SHDN을 언급 안 함.

**권장 수정**:
- SHDN은 **내부 풀업으로 미연결 시 항상 ON** → 설계 의도(상시 ON)와 맞음. 다만 **"SHDN = 미연결(NC), 내부 풀업으로 상시 ON"**을 BOM/배치도 주석에 명시해 납땜 시 혼선 방지.
- 납땜 전 **실제 보드 실크의 핀 순서를 육안 확인**(VIN/VOUT 좌우, GND 위치)하고 배치도 홀과 1:1 대조할 것.

### 🟡 M-4. 디커플링 캡이 "센서 5mm 이내"가 아니라 "커넥터 5mm 이내"

**근거**: §2.x·§3 Step4는 100µF+100nF를 "센서 핀에서 5mm 이내"로 지시하지만, 실제 센서는 **케이블로 연결된 원격(로봇 엔드이펙터)** 모듈. 기판 커넥터 옆 캡은 센서에서 케이블 길이만큼 멀어짐 → 고주파 디커플링 효과 감소.

**권장 수정**: 가능하면 **센서 모듈 자체의 VCC-GND에도 100nF(+가능하면 10µF) 추가** 배치. 기판 측 캡은 벌크/버스 안정화용으로 유지. UART/전원 케이블은 §8.3대로 15cm 이내.

## 4. 낮은 우선순위 / 문서 정합성

### 🟢 L-1. 캐패시터 명칭(C1/C2) 표기 혼란
§1.3 표에서 `C1 = 100µF 전해 2개`인데 비고에 "C1: 디커플링, C2: ADC 필터"로 적어, 같은 100µF 2개를 C1로 묶으면서 역할은 둘로 나눔. `C2`는 다시 100nF 세라믹. **명칭 충돌**로 조립 시 혼동 가능.
→ **권장**: `C1=센서 디커플링 100µF`, `C2=ADC 필터(세라믹, C-1 수정 반영)`, `C3=100nF 세라믹`으로 **고유 번호 재배정**.

### 🟢 L-2. 역극성 보호 없음
AA 홀더 리드(+/−)를 반대로 연결하면 Pololu VIN 역전 → 손상 가능(S7V8F3는 역극성 보호 없음).
→ **권장**: 입력에 직렬 쇼트키 다이오드(전압손실 감수) 또는 **커넥터 키잉/색상 규칙 엄수** + 첫 통전 전 멀티미터 극성 확인(§7.1에 한 줄 추가).

### 🟢 L-3. 펌웨어 기본값이 Option A로 되어 있음
마스터 가이드의 `readBatteryVoltage()`는 `battV = adcV / 0.2126`(Option A) 가 활성, Option B(`adcV * 2.0`)는 주석 처리. **이번 빌드는 Option B** → 반드시 식을 Option B로 교체. (`option_b_guide_v3.md` §6엔 맞게 적혀 있으나, 실제 코드 파일 수정 누락 주의.)

### 🟢 L-4. 배치도 ESP32 핀 위치 육안 검증 요망
`ESP32_C3_pinmap.png` 기준 물리 배치는 **왼쪽 열(위→아래): 5V, GND, 3V3, GPIO4, GPIO3, GPIO2, GPIO1, GPIO0 / 오른쪽 열: GPIO5, 6, 7, 8, 9, 10, 20, 21**. 즉 **GPIO3(ADC)·GPIO2(EN)는 왼쪽 열**, **GPIO20/21(UART)·GPIO8(LED)은 오른쪽 열**.
배치도(`option_b_top_component_side_v3.jpg`)의 핀 라벨 위치가 저해상도라 GPIO2/GPIO3 상하순서가 모호함.
→ **권장**: 납땜 전 **실제 보드를 소켓에 꽂고 각 GPIO 홀이 핀맵과 1:1로 맞는지 멀티미터 도통으로 확인**. 특히 GPIO3(분배점), GPIO20/21(크로스) 도통 체크.

## 5. 납땜 전 최종 체크리스트 (수정 반영본)

- [ ] **C-1**: ADC 분배점 필터를 100µF 전해 → **100nF~1µF 세라믹**으로 교체 (가능하면 분배저항 100k/100k)
- [ ] **C-2**: `LOW_BATT_THRESHOLD_B = 2.8`로 상향, 잔량표·전원경로 표기를 2.7V 차단 기준으로 정정
- [ ] **C-3**: 센서 EN을 GPIO2 → **GPIO10**(또는 미사용)로 변경, 또는 GPIO2에 10k 풀업
- [ ] **M-1**: 3.3V 버스에 470µF 벌크캡 + VIN에 100~220µF 추가, 배터리 운용은 BLE 우선
- [ ] **M-2**: `analogReadMilliVolts()`/eFuse 캘리브레이션 적용
- [ ] **M-3**: Pololu **SHDN = NC(상시 ON)** 명시, 실제 보드 핀 순서 육안 대조
- [ ] **M-4**: 센서 모듈 끝단에 100nF(+10µF) 디커플링 추가
- [ ] **L-3**: 펌웨어 배터리 식 **Option B(`adcV*2.0`)** 로 교체 확인
- [ ] **L-4**: ESP32 전 핀 홀 ↔ 핀맵 도통 1:1 검증 (GPIO3/20/21 필수)
- [ ] 통전 순서 준수: ① 홀더 극성 확인 → ② 스위치 ON, **Pololu VOUT 3.3V±0.1V 무부하 확인** → ③ 그 후에만 ESP32·센서 연결
