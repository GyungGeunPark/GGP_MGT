### 1.4 저항 (v4 변경)

| # | 부품 | 사양 | 컬러코드 (5밴드 1%) | 수량 | 용도 |
|---|------|------|---------------------|------|------|
| R1, R2 | 저항 | **100kΩ 1/2W ±1%** | 갈-검-검-주-갈 | 2 | 전압분배기 (v3: 220kΩ) |

> **v4 변경 이유**: 220kΩ → 100kΩ로 낮춰 분배점 소스 임피던스를 110kΩ→**50kΩ**로 감소.
> ESP32-C3 ADC 입력에 더 안정적입니다. 분배기 **상시 소모 전류**는 3.0V÷200kΩ = **15µA**(전지 수명 영향 미미).
> ⚠ 이 15µA는 **분배 비율을 만드는 정상 동작 전류**이지 측정 오차원이 아닙니다. 실제 오차원은 ①C3 캐패시터 누설과 ②ESP32 ADC 입력 누설인데, **C3을 저누설 세라믹/필름으로 쓰면** 둘 다 nA급 → 50kΩ에 걸쳐도 <1mV로 무시 가능. (전해를 쓰면 µA급 누설이 이 노드에 흘러 큰 오차 → 그래서 v4에서 세라믹으로 교체)

## 2. 회로 구성

### 2.1 전원 경로

```
[AA 건전지 × 2]
  직렬 → 3.0V(신품) ~ 2.7V(컨버터 차단점)     ← ★v4: 1.8V 아님! UVLO 2.7V
       │
  [홀더 내장 ON/OFF 스위치]
       │
  빨간선(+) ──────────────> Pololu S7V8F3 VIN ──┬── [C5: 100~220µF] (★v4 VIN 벌크)
  검은선(─) ──────────────> Pololu S7V8F3 GND   │
       (SHDN = 미연결/NC, 상시 ON)               GND
                                                 │
                                         3.3V 고정 출력
                                                 │
                              ┌──────────────────┼── [C4: 470µF] (★v4 3.3V 벌크)
                              │                  │
                         ESP32-C3 3V3       JRT U81 VCC
```

> **★ v4 — 컨버터 차단 전압**: S7V8F3는 입력이 **약 2.7V 미만**이면 3.3V 출력을 끊습니다(UVLO).
> 부하·배터리 내부저항으로 단자전압이 2.7V 밑으로 떨어지면 시스템이 정지하므로, **알카라인을 1.8V까지 쓸 수 없습니다**. 실사용 하한은 ~2.7V입니다.

### 2.2 전압분배기 (배터리 모니터링) — v4

```
BAT(+) ─[R1: 100kΩ 1/2W ±1%]─┬──> ESP32 GPIO3 (ADC1_CH3)
                              │
                       [R2: 100kΩ 1/2W ±1%]
                              │
                       [C3: 100nF~1µF 세라믹]  (무극성, 저누설)  ★v4
                              │
                             GND
```

**계산값:**
- Vadc = Vbat × 0.5 (1:1 분배, R1=R2)
- 신품 3.0V → Vadc = 1.50V
- 차단 2.7V → Vadc = 1.35V
- 소스 임피던스: 100kΩ ∥ 100kΩ = **50kΩ**
- 분배기 상시 소모 전류: 3.0V ÷ 200kΩ = **15µA** (정상 동작 전류, 측정 오차 아님)
- 필터 시정수(C3=1µF 기준): 50kΩ × 1µF = **50ms** (v3 100µF=5.5s 대비 100배 빠름)

> **★ v4 — 전해 금지**: ADC 분배점은 고임피던스 노드입니다. 여기에 전해(100µF)를 쓰면 ①정착에 수~수십 초 걸려 부팅 직후 측정이 틀리고 ②전해 누설(수 µA)이 분배전류를 잠식해 잔량을 과소 표시합니다. **세라믹/필름(C3)** 만 사용하세요.

### 2.3 UART 연결 (크로스 필수)

```
JRT U81 TX ──────────────────> ESP32 GPIO20 (RX)  [초록 26AWG]
ESP32 GPIO21 (TX) ───────────> JRT U81 RX          [파랑 26AWG]
```

> ⚠ **TX↔RX 크로스 연결 필수**: 동일 핀끼리 연결하면 통신 불가.
> (`ESP32_C3_pinmap.png` 확인: GPIO20 = RX, GPIO21 = TX)

### 2.4 전체 연결 요약 (v4)

| 연결 출발 | 연결 도착 | 와이어 색 | 게이지 |
|-----------|-----------|-----------|--------|
| 홀더 빨간선(+) | Pololu VIN (+ C5) | 빨강 | 24AWG |
| 홀더 검은선(─) | Pololu GND | 검정 | 24AWG |
| Pololu VOUT | ESP32 3V3, 센서 VCC, C4(+) | 노랑 | 24AWG |
| Pololu GND | GND 공통 버스, C4(─) | 검정 | 24AWG |
| 센서 TX | ESP32 GPIO20 (RX) | 초록 | 26AWG |
| ESP32 GPIO21 (TX) | 센서 RX | 파랑 | 26AWG |
| 전압분배 출력(분배점) | ESP32 GPIO3 | 보라 | 26AWG |
| **ESP32 GPIO10** | 센서 EN | 흰색/회색 | 26AWG (선택) ★v4 변경 |

> **★ v4 — EN 핀 변경**: 센서 EN 제어는 **GPIO10**을 사용합니다. v3의 GPIO2는 ESP32-C3 **부팅 스트래핑 핀**이라 부팅 시 레벨이 샘플링되어 간헐적 부팅 실패를 유발할 수 있습니다. EN을 쓰지 않을 거면 선을 아예 생략해도 됩니다(센서는 EN 미연결 시에도 동작).

## 4. 만능기판 조립 절차

### 4.1 준비물 확인

- [ ] 납땜 인두 (330~360°C), 납(Sn63/Pb37 또는 무연)
- [ ] 플럭스, 이선(납 제거), 멀티미터, 루페, 와이어 스트리퍼/니퍼
- [ ] IPA(이소프로필 알코올) — 플럭스 세척용

### 4.2 조립 순서

#### Step 1: 핀헤더 소켓 납땜 (ESP32용)
1. 암 핀헤더 소켓(9핀 × 2열)을 **열5~17, 행H~P**에 삽입
2. ESP32-C3 임시 장착 → 정렬 확인 → 각 핀 납땜 → ESP32 분리
3. **소켓 사용 이유**: 펌웨어 업로드 시 ESP32만 분리해 USB 연결

#### Step 2: Pololu S7V8F3 장착
1. 핀헤더 또는 양면테이프+와이어로 고정
2. **VIN, GND, VOUT, GND** 위치 확인. **SHDN은 납땜하지 않음(NC)**
3. 실크 인쇄로 VIN/VOUT 방향 재확인 후 기판 홀에 납땜

#### Step 3: 전압분배기 조립 (v4)
1. **R1(100kΩ)**: 열19, 행G~K 수직 삽입 후 납땜
2. **R2(100kΩ)**: 열19, 행K~N 수직 삽입 (K 홀 공유 = 분배점)
3. **C3 ADC필터(100nF~1µF 세라믹, 무극성)**: 열21, 행K~M
   - **무극성**이므로 방향 무관. **전해 사용 금지!**

#### Step 4: 센서 디커플링 (C1·C2)
1. **C1 100µF 16V 전해**: 열3, 행R~S — (+)→R행(VCC), (─)→S행(GND), **극성 확인**
2. **C2 100nF 모노**: 열6, 행R~S (무극성), C1과 병렬
3. 센서 커넥터에서 **5mm 이내** 배치

#### Step 5: 전원 벌크캡 (v4 신설)
1. **C4 470µF 16V 전해**: 열24~26, 행Q~S — (+)→3.3V버스, (─)→GND, **극성 확인**
2. **C5 100~220µF 16V 전해**(WiFi 사용 시 권장): Pololu VIN 인접 — (+)→VIN, (─)→GND

#### Step 6: 센서 커넥터 5핀 핀헤더
1. 5핀 수 핀헤더를 **열10~14, 행S**에 납땜
2. 핀 순서: VCC(10) / GND(11) / TX(12) / RX(13) / EN(14)

#### Step 7: 배터리 홀더 연결점
1. 스크류 터미널(2핀) 또는 직납땜
   - BAT+ (홀더 빨간선) → 열2, 행B
   - BAT─ (홀더 검은선) → 열4, 행B
2. **★ 통전 전 극성 확인**: S7V8F3는 역극성 보호가 없습니다. 첫 통전 전 멀티미터로 (+)/(─) 확인. 커넥터 키잉/색상 규칙 엄수.
3. 스트레인 릴리프 (케이블 타이로 기판에 고정)

### 4.3 하면 납땜 배선 순서

배선은 **기판 하면**에서 와이어로 연결합니다. 하면 작업 시 **좌우 반전(미러)** 주의.

```
① GND 버스 (검정 24AWG) — 가장 먼저
   BAT─, Pololu GND, ESP32 GND, 센서 GND,
   C1(─), C4(─), R2 하단, C3(─) 모두 공통 연결

② 3.3V 버스 (노랑 24AWG)
   Pololu VOUT → ESP32 3V3 + 센서 VCC + C1(+) + C4(+)

③ BAT+ 직결 (빨강 24AWG)
   홀더 BAT(+) → Pololu VIN (+ C5(+))   ← 스위치는 홀더 내장

④ 전압분배기 출력 (보라 26AWG)
   분배점(R1/R2 중간) → ESP32 GPIO3

⑤ UART 크로스 (초록/파랑 26AWG)
   센서 TX → GPIO20(RX)  [초록]  ← 크로스!
   GPIO21(TX) → 센서 RX  [파랑]  ← 크로스!

⑥ EN 제어선 (회색/흰색 26AWG, 선택) ★v4
   ESP32 GPIO10 → 센서 EN     (구 GPIO2에서 변경)

⑦ 전체 점검 — 쇼트·도통·콜드솔더 확인, IPA로 플럭스 세척
```

> **★ 납땜 후 필수 검증**: ESP32 소켓에 보드를 꽂고, 각 GPIO 홀이 `ESP32_C3_pinmap.png`와 1:1로 맞는지 **멀티미터 도통**으로 확인하세요. 특히 GPIO3(분배점), GPIO20/21(크로스), GPIO10(EN).

## 5. 전원 ON/OFF 방법

```
[홀더 내장 스위치]
  ON  → 건전지 → Pololu → 3.3V 출력 → 시스템 동작
  OFF → 회로 차단 → 소비 전류 0 (전압분배기도 함께 차단)
```

**대기 전류**: 스위치 OFF 시 완전 차단(누설 0).
**ON 전환 시**: Pololu 기동 ~1ms → ESP32 부팅 ~500ms → 센서 초기화 ~300ms → 동작.

> **장기 보관**: 스위치 OFF + 건전지 분리 권장(누액 방지).

## 6. 펌웨어 핵심 설정 (v4)

> 📄 **전체 코드는 `option_b_firmware_v4.ino`** (BLE+WiFi 통합, 런타임 전환). 아래는 v4 핵심 발췌입니다.
> 빌드/업로드 검증 절차는 **`option_b_build_verify_v4.md`** (arduino-cli), PC 수신은 **`pc_receiver_v4.py`** 참고. 전체 소프트웨어 구성은 §10 참조.

```cpp
// ── 핀 정의 (v4) ──
#define SENSOR_RX_PIN     20    // ← 센서 TX
#define SENSOR_TX_PIN     21    // → 센서 RX
#define SENSOR_EN_PIN     10    // ★v4: GPIO2 → GPIO10 (스트래핑 핀 회피)
#define BATTERY_ADC_PIN   3     // ADC1_CH3
#define LED_PIN           8     // 온보드 LED

// ── 저전압 임계값 (v4) ──
#define LOW_BATT_WARN_B       2.90  // ★v4: 경고 (WiFi 끄고 BLE 전환 권장)
#define LOW_BATT_SHUTDOWN_B   2.80  // ★v4: 안전 종료/딥슬립 (UVLO 2.7V 위 여유 확보)
// 주의: WiFi 부하 시 단자전압이 순간 강하하므로, 무부하 2.8V여도 피크에서 2.7V(UVLO)
//       밑으로 내려가 하드 리셋될 수 있음 → 경고 시점(2.9V)에 WiFi를 끄는 것이 안전.

// ── 배터리 전압 읽기 (Option B + eFuse 캘리브레이션) ──
float readBatteryVoltage() {
    uint32_t sum_mv = 0;
    for (int i = 0; i < 16; i++) {
        sum_mv += analogReadMilliVolts(BATTERY_ADC_PIN);  // ★v4: eFuse 보정값(mV)
    }
    float adcV = (sum_mv / 16.0) / 1000.0;   // mV → V
    float battV = adcV * 2.0;                // ★Option B: 100k/100k 1:1 분배기
    return battV;
}

void setup() {
    // ...
    pinMode(SENSOR_EN_PIN, OUTPUT);
    digitalWrite(SENSOR_EN_PIN, HIGH);       // GPIO10으로 센서 활성화
    // ADC: analogReadMilliVolts는 attenuation/eFuse를 내부 처리
    delay(300);                              // ★v4: ADC 필터 안정 대기
    lastBatteryV = readBatteryVoltage();
    // 첫 1~2회 측정값은 신뢰하지 말 것 (필터 정착 전이면 버림)
}
```

**전압-잔량 매핑 (알카라인, v4 — 컨버터 차단 2.7V 기준):**

| 배터리 전압 | Vadc | 잔량 / 동작 |
|------------|------|------|
| 3.0V | 1.50V | 100% |
| 2.9V | 1.45V | 20% — **경고: WiFi 끄고 BLE 전환** |
| 2.8V | 1.40V | 10% — **안전 종료 / 딥슬립** |
| 2.7V | 1.35V | 0% — 컨버터 차단(UVLO) |

> **★ v4 변경 핵심**: 단순 "경고 1단계"가 아니라 **2단계**로 둡니다.
> - **2.9V 경고**: 무부하 전압이 여기 도달하면 WiFi를 꺼 BLE로 전환(피크 전류↓). 이유는 WiFi 부하 시 단자전압이 순간 강하해, 무부하 2.8V여도 피크에서 **2.7V(UVLO) 밑으로 떨어져 하드 리셋**될 수 있기 때문.
> - **2.8V 종료**: 안전 종료 또는 딥슬립으로 UVLO(2.7V) 위에 여유를 확보(그레이스풀 셧다운).
> v3의 2.0~2.4V 매핑은 이 컨버터에선 도달 불가능한 값이라 폐기.

## 7. 테스트 절차

### 7.1 전원 테스트
```
1. 건전지 홀더에 AA 알카라인 2개 삽입, 극성 확인
2. 홀더 스위치 OFF 확인
3. 멀티미터로 Pololu VIN-GND = 0V 확인 (OFF)
4. 스위치 ON → VIN-GND ≈ 3.0V, SHDN 미연결 상태에서 동작 확인
5. VOUT-GND = 3.3V ±0.1V 확인  ← 반드시 이 단계 후 ESP32·센서 연결
6. ESP32, 센서 연결
```

### 7.2 UART 통신 테스트
```cpp
HardwareSerial LaserSerial(0);
void setup() {
    Serial.begin(115200);
    LaserSerial.begin(19200, SERIAL_8N1, 20, 21);  // RX=20, TX=21
    delay(300);
    LaserSerial.write('O');   // 레이저 ON
    delay(100);
    LaserSerial.write('D');   // 거리 측정
}
void loop() {
    if (LaserSerial.available())
        Serial.println(LaserSerial.readStringUntil('\n'));
}
// ✅ Pass: "X.XXXm, XXXX" 형식 응답
// ❌ Fail: TX/RX 크로스(GPIO20↔21) 재확인
```

### 7.3 배터리 ADC 테스트 (v4 추가)
```
1. 멀티미터로 분배점 전압 실측 → 시리얼의 adcV와 비교
2. 신품 전지에서 battV ≈ 3.0V 표시 확인
3. 전원 인가 직후 1~2초간 측정값이 낮게 나오면 정상(필터 정착) — 이후 안정값 사용
```

### 7.4 무선 테스트
- **BLE**: nRF Connect에서 "JRT-U81-LDS" 검색
- **WiFi**: 시리얼에서 "WiFi 연결 완료! IP: x.x.x.x" 확인

## 8. 트러블슈팅 (v4)

| 증상 | 원인 | 해결 |
|------|------|------|
| 스위치 ON해도 전원 안 들어옴 | 홀더 접촉 불량 / SHDN 오접속 | 홀더 출력 확인, SHDN이 GND에 붙지 않았는지 확인 |
| Pololu 출력 3.3V 아님 | 입력 < 2.7V (UVLO) | 건전지 교체 |
| 배터리 잔량 표시가 계속 낮음 | **ADC 필터에 전해 사용** | C3을 세라믹으로 교체(v4) |
| 부팅이 간헐적으로 실패 | **GPIO2 등 스트래핑 핀 사용** | EN을 GPIO10으로 이설(v4), GPIO2 미연결 |
| 센서 통신 없음 | TX/RX 뒤바뀜 | GPIO20↔GPIO21 크로스 재확인 |
| WiFi 켜면 ESP32 리셋 | 알카라인 ESR + 돌입전류 | C4(470µF)+C5 확인, 신품 전지, BLE 모드 권장 |
| ADC 값 부정확 | 캘리브레이션 미적용 | analogReadMilliVolts 사용(v4) |
| 경고 없이 갑자기 꺼짐 | 임계값 < UVLO | 2단계 임계값 2.9V/2.8V (v4) |
| WiFi 중 저전압에서 리셋 | 부하 강하로 UVLO 도달 | 2.9V 경고 시 WiFi OFF → BLE 전환(v4) |

## 10. 소프트웨어 구성 (펌웨어 · PC 수신기 · 빌드)

v4 시스템은 **펌웨어(ESP32) ↔ PC 수신기**가 한 쌍으로 동작하며, 둘은 **13바이트 패킷**으로 약속됩니다.

### 10.1 데이터 흐름

```
JRT U81 ──UART(19200)──▶ ESP32-C3 ──[BLE NUS notify | WiFi UDP]──▶ PC 수신기
                          (option_b_firmware_v4.ino)              (pc_receiver_v4.py)
```

### 10.2 무선 패킷 포맷 (펌웨어 ↔ 수신기 공통)

| 오프셋 | 타입 | 필드 | 비고 |
|--------|------|------|------|
| 0 | uint8 | 센서 ID (0x01) | |
| 1–4 | float32 | distance_mm | 리틀엔디안 |
| 5–8 | uint32 | timestamp_ms | ESP `millis()` |
| 9–12 | float32 | battery_v | 리틀엔디안 |
| 13–14 | uint16 | signal_quality (SQ) | 낮을수록 좋음 · `0xFFFF`=미상 ★v4 |

→ Python `struct` 포맷 **`'<BfIfH'` (총 15바이트)**. 펌웨어 `memcpy` 배치와 1:1 일치(검증 완료).
→ 배터리 잔량 %는 웹 브리지가 전압→잔량 매핑(3.0V=100%, 2.7V=0%)으로 산출해 UI에 표시.

### 10.3 펌웨어 (`option_b_firmware_v4.ino`)

- **BLE(NimBLE NUS) + WiFi UDP 통합** 단일 스케치. `#define DEFAULT_COMM_MODE` 로 기본 모드 선택.
- **저전압 2단계**: 2.90V → WiFi 끄고 BLE 폴백 / 2.80V → 레이저 OFF + 딥슬립(EN 핀 hold).
- v4 하드웨어 반영: EN=GPIO10, `analogReadMilliVolts()`, 첫 ADC 측정 폐기, 센서 UART는 UART1 매핑.
- WiFi 모드 빌드법은 §8(빌드 문서)·파일 상단 주석 참고.

### 10.4 PC 수신기 (`pc_receiver_v4.py`)

```bash
python3 pc_receiver_v4.py udp --csv log.csv     # WiFi UDP 4210 수신 + CSV 로깅
python3 pc_receiver_v4.py ble --laser-on        # BLE 'JRT-U81-LDS' 연결 + 레이저 ON
```
- UDP는 표준 라이브러리만, BLE는 `pip install bleak` 필요.
- 거리/배터리/타임스탬프 실시간 출력, 저전압(<2.90V) 경고, CSV 기록.

**웹 UI 연동** (`../lsd_interface/wireless_bridge_v4.py`): 무선 패킷을 기존 `lsd_interface` 웹 UI의 WebSocket 스키마(`/ws`, `{type:distance|status|voltage|ack}`)로 변환해 **같은 UI를 무선으로 재사용**. 엔드투엔드 스모크 테스트 통과(UDP 패킷→거리 표시→명령 왕복).
```bash
pip install fastapi "uvicorn[standard]" websockets   # (+ BLE면 bleak)
python3 ../lsd_interface/wireless_bridge_v4.py --mode udp --port 4210   # http://localhost:8000
```

### 10.5 빌드/검증 (`option_b_build_verify_v4.md`)

arduino-cli 헤드리스 빌드 절차(설치→코어→라이브러리→컴파일→업로드). FQBN `esp32:esp32:esp32c3:CDCOnBoot=cdc`. CI에 그대로 사용 가능.
**✅ 실측 검증**: arduino-esp32 코어 3.3.8 + NimBLE 2.5.0에서 컴파일 성공(플래시 92%/1.21MB). 92%로 빠듯하니 기능 추가 시 `PartitionScheme=huge_app` 사용.
